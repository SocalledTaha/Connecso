# Project State

Updated: 2026-10-02

## Product scope

CONNECSO Client targets Android only and uses Xray-core as its only VPN runtime. Windows and iOS implementation are out of scope. Preserve all 28 approved requirements and earlier explicit requests; improve the implementation additively and do not drop a feature to shorten build time or simplify the code.

```text
Subscription import → Fetch/Normalize/Validate → Atomic cache
  → ProbeEngine → SmartSelector → Xray configuration
  → Android VpnService → verify actual HTTPS connectivity → Connected
```

## Requirement status

1. **Subscription import:** clipboard and QR camera/image import are implemented. Auto detection/parsing normalizes supported VLESS, VMess, Trojan, Shadowsocks, compatible JSON outbounds, and Clash YAML.
2. **Independent Subscription Engine:** HTTPS fetch, validation, encrypted cache, quota/profile metadata, and atomic replacement are implemented. Android WorkManager now schedules connected-network refresh for all saved HTTPS subscriptions, including while the UI is closed; Android may defer timing for power policy.
3. **Xray core:** Xray configuration, Android runtime bridge, start/stop/restart/reload/stats/error handling exist. Xray is the only runtime; no core selection UI.
4. **ProbeEngine:** bounded concurrent protocol/core probes, latency and persisted probe history exist. Probe scheduling while the app is closed and reachability history policy remain to complete.
5. **SmartSelector:** success/failure, recency, stability, health, latency, and hysteresis are implemented. Connection-establishment duration is now persisted per node and included in selection scoring.
6. **Connection verification:** real routed HTTPS checks gate Connected state.
7. **Automatic failover:** checks current tunnel health and retries another eligible Xray node with verification.
8. **Network recovery:** UI-process health polling and node failover exist. The Android VPN service now tracks underlying network changes and requests redelivery after service-process death. Sleep/resume, failover while the UI isolate is stopped, and full crash recovery still need device validation and lifecycle integration.
9. **Subscription recovery:** route ordering and real HTTP transport interface exist. Wiring recovery into refresh transport remains incomplete.
10. **Control-plane recovery:** signed manifest parsing, Ed25519 verification, allowlist and validity checks exist. Production manifest endpoint and pinned public key are owner-supplied values; recovery remains fail-closed until configured. Atomic manifest storage/cooldowns need integration.
11. **Android VpnService:** TUN, DNS, foreground service, Android per-app routing and Xray process bridge exist. The packet path is Android VpnService TUN → HEV 2.18.0 → local Xray SOCKS5 inbound. The Phase 1 baseline is IPv4-only: the Android builder and HEV configuration no longer add IPv6 addresses/routes. Xray uses `1.1.1.1` and `8.8.8.8`, routes port 53 to its DNS outbound, and prefers IPv4 answers. UDP/443 is allowed through Xray for QUIC testing. HEV is built from pinned source and exact submodule revisions with Android NDK 27.2.12479018 and API 24, preserving the app's Android 7.0+ minimum. Runtime Chrome/browser validation remains required on a device.
12. **Split Tunneling:** OFF / Use Proxy / Bypass, user app icons, search, hidden system apps by default, Google treated as user apps, bulk selection, retained selections, and list import/export exist. Persian title is «جداسازی برنامه‌های ایرانی».
13. **Home UI:** minimal branded home is implemented. Theme-specific transparent CONNECSO marks are used; brand stays at the left while language/theme actions stay at the right in both EN and FA. The general header menu is removed. Working-tree updates add saved subscription edit/refresh/delete/pin actions, immediate profile selection, clipboard/QR import, and email display; selection no longer interrupts an existing VPN session.
14. **Connection ring:** animated control ring exists; the disconnected appearance is neutral and the moving arc is reserved for connection progress. An Android Quick Settings tile toggles the last app-started profile.
15. **Dynamic map:** local Natural Earth country geometry, uniform geographic scaling, theme-aware paint, phase-derived map states, verified-only destination transition, country/city framing, reduced-motion handling, and destination pulse are implemented. The Home map fades into the background, removes graticules and Antarctica, and labels the coordinate-anchored exit city; if city metadata is unavailable, the resolver extracts a known country from the connection name and uses the bundled country center without a city marker. Map geometry is isolated from marker pulse repainting. Natural Earth DBF NUL padding was preventing ISO country matching; the generator and bundled asset now normalize country codes. No GPS or location permission is used. Current visual correction needs CI and Android device validation.
16. **Exit location:** explicit coordinates and metadata, bundled known-city resolution, and whole-word server-name matching are supported. Country-only locations have no fabricated city or city marker; unknown locations stay neutral.
17. **Usage:** a single unified Home card shows active Xray session total plus inline download/upload, separately from cumulative provider quota and remaining. Finite quota progress is derived from provider usage/total and clamped; an explicit zero total is treated as unlimited, while missing or malformed values remain unavailable. Session values remain absent until live stats arrive, and cached quota remains independent of session traffic.
18. **Quota metadata:** Happ-compatible `subscription-userinfo` headers and plain/base64 body comments are parsed. Verified the user-provided subscription endpoint returns the standard 3x-ui header with upload/download/total/expire fields; `expire=0` is treated as an explicit no-expiry state. The private endpoint itself is not stored in the repository or logs.
19. **Connection status:** lifecycle states and failures are shown. Ping/health text is suppressed when the last probe is missing or older than two minutes. Stable requires a fresh healthy probe, recorded history, at least 70% success score and latency no greater than 1500 ms; otherwise a fresh result is labeled Unstable. Understandable category-specific failures remain to improve.
20. **Localization:** EN/FA and RTL/LTR support exist.
21. **Themes:** Light/Dark switching and home shortcuts exist.
22. **Startup:** encrypted cached nodes render before asynchronous refresh/probing.
23. **Persistence:** secure subscription/node cache, settings, SQLite usage/connection/probe history and schema migrations exist. Add any missing recovery-state persistence during recovery integration.
24. **Privacy:** credentials/subscription URLs are excluded from structured log fields; no private key is bundled.
25. **Structured logging:** redacted allowlisted categories include subscription, probe, VPN, Xray and recovery.
26. **Tests:** parser, metadata, quota, selector/hysteresis, connection state/failover, database/migrations, recovery manifests, split tunneling, map, localization, and UI regression tests exist. Expand coverage with each remaining implementation.
27. **Documentation:** architecture, build, debugging, security, platform, probe, routing, split tunneling, subscription engine and UI specification are maintained.
28. **Private GitHub delivery:** private repository and Android CI are configured; validate each milestone with analyze, tests and APK build before reporting completion.

The current network baseline keeps Xray Mux disabled (no UI setting); imported subscriptions remain saved on sign-out and can be renamed; Split Tunneling list import/export remains available. This Mux setting supersedes the earlier request to enable Mux by default.
