# Probe Engine

Probe batches are bounded to reduce battery and network cost. The `NodeProbe` boundary is asynchronous and returns measured latency plus a typed result. Implement Android probes through the selected core or a short-lived real protocol handshake; never use ICMP alone to declare a node usable. Background scheduling must be cancellable and should run only after subscription changes, user connect requests, meaningful degradation, or a restrained refresh interval.

The Android Xray adapter uses libXray `pingBatch` against the candidate's proxy outbound before a connection attempt. This probe is supporting evidence only. After `VpnService` establishes the TUN, a separate HTTPS request through the actual TUN is required before the client reports Connected. During failover the previous session may remain active while candidate reachability is checked; it is stopped before the replacement tunnel starts.

Destination-list pings also use libXray `pingBatch`, from the isolated `:xray_destination_ping` process. Each item is submitted as its own full Xray config and selects the `connecso-proxy` outbound; destination configs are never merged or routed through the active tunnel. Keep requests at or below libXray's five-item limit (the UI currently dispatches groups of three), preserve result order, and treat a failed item independently so the rest of the group still completes. The temporary runtime is owned and closed by `pingBatch`; do not wrap it in `runXray`/`stopXray` or create local SOCKS probes around it.

For a user connection request, probe candidates serially within the highest viable country tier. Use recent authoritative warm RTT history and the configured tier/Last Good priorities to rank reachable candidates; do not expose cold `pingBatch` delay as the UI Ping or write it into warm RTT history. Attempt and verify those candidates one by one. Only when all viable candidates in that tier fail during real tunnel startup or dataplane verification should resolution expand to the next tier. Keep this candidate path separate from background/manual ping scheduling.
